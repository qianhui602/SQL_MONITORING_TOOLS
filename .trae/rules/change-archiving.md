# 变更归档与上下文压缩归档规则

**自动归档模式已开启，触发条件满足时无需询问，立即执行。**

你是一位严格遵循规范的代码助手。在整个对话过程中，你必须无条件遵守以下"变更归档"与"上下文压缩归档"规则。

## 一、变更归档规则

1. 每次生成或修改项目代码后，你必须创建一条结构化的变更归档记录。
2. 记录必须使用 Markdown 格式，并自动保存到项目中的 `docs/changelog/` 目录（如不存在，则使用 `.trae/changes/` 目录）。
3. 归档文件命名格式：`YYYY-MM-DD-HHMM_简短描述.md`。
4. 每条记录必须包含以下内容（使用该模板）：

```markdown
# 变更记录 - <简短描述>

- **日期**: YYYY-MM-DD HH:MM
- **类型**: 新增功能 / Bug修复 / 逻辑修改 / 依赖变更 / 文件删除 / 配置变更
- **影响范围**: 受影响的模块或文件列表

## 变更内容
<详细描述本次变更的内容>

## 变更原因
<说明为什么要做这个变更>

## 涉及文件
| 文件路径 | 操作（新增/修改/删除） | 说明 |
|---------|---------------------|------|
```

5. 以下情况必须触发归档：新增功能/模块、修改已有逻辑、修复 Bug、依赖或配置变更、删除文件或废弃代码。
6. 任务完成后，你必须在回复末尾明确告知："变更归档已生成：`<文件路径>`"。

## 二、上下文压缩归档规则

1. 当对话轮次超过 15 轮，或用户明确要求"总结/压缩上下文"，或一个功能阶段结束时，你必须生成上下文压缩归档。
2. 压缩归档应提炼对话中的关键信息，丢弃冗余细节，保存到 `.trae/context/` 目录，文件名为 `session-YYYY-MM-DD.md` 或 `context-summary-<主题>.md`。
3. 归档必须包含以下内容：

```markdown
# 会话上下文归档 - YYYY-MM-DD

## 会话目标
<原始目标>

## 已完成事项
- [x] 事项（关键决策或产出）

## 进行中
- [ ] 当前进度与阻塞点

## 重要决策与原因
- 决策及理由

## 待解决问题
- 未解决的开放问题

## 关键文件快照
| 文件路径 | 用途 | 最后状态 |

## 下一步建议
<为新会话准备的明确起点>
```
