# 变更记录 - 修复死锁导出缺SQL与慢查询7天导出失败

- **日期**: 2026-09-02 14:15
- **类型**: Bug修复
- **影响范围**: `backend/app/routers/export.py`、`frontend/src/api/index.js`

## 变更内容
1. **死锁监控导出缺少 SQL 语句**：`export_deadlocks` 原先只查询 `DeadlockEvent` 本表，导出 CSV 仅含 6 列基础信息。本次增加 `selectinload(DeadlockEvent.deadlock_sqls)` 预加载每个死锁事件关联的 SQL 明细，并在导出中新增「关联SQL语句」列：
   - 每条语句格式为 `[会话 {session_id}]\n{sql_text}`，同一事件的多个语句以空行分隔；
   - 按 `DeadlockSql.session_id` 排序，空 SQL 文本跳过；
   - `csv.writer` 自动对内嵌换行符加引号转义，Excel 可正常展示多行单元格。
2. **慢查询分析 7 天数据导出失败**：`export_slow_queries` 原先使用 `result.scalars().all()` 将最多 50000 行（每行含完整 SQL 大文本）一次性载入内存后再流式输出，7 天数据量下导致内存暴涨、响应缓慢直至前端超时报错。本次改为 `db.stream(stmt.execution_options(stream_results=True))` 使用 asyncpg 服务端游标，在行生成器内逐行 `async for` 读取，实现真正的低内存流式导出。
3. **前端导出超时提升**：`exportDeadlocks` / `exportSlowQueries` 请求超时由 120 秒提升至 600 秒，避免大数据量导出中途被 axios 超时中断。

## 变更原因
用户反馈两个问题：死锁监控导出的 CSV 中没有查询语句内容（截图确认仅 6 列）；慢查询分析选择最近 7 天数据导出时失败。
