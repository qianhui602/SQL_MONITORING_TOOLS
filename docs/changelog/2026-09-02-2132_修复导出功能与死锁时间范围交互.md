# 变更记录 - 修复导出功能与死锁时间范围交互

- **日期**: 2026-09-02 21:32
- **类型**: Bug修复 / 逻辑修改
- **影响范围**: `frontend/src/views/SlowQueries.vue`、`frontend/src/views/Deadlocks.vue`、`frontend/src/i18n/zh-CN.js`、`frontend/src/i18n/en-US.js`

## 变更内容
1. **慢查询分析导出无反应**：`SlowQueries.vue` 模板中已有导出按钮，但脚本缺少 `exporting` 状态、`onExport` 函数及相关 import。本次补全：
   - 导入 `exportSlowQueries`（@/api）与 `downloadBlob`/`buildExportFilename`（@/utils/export）
   - 新增 `exporting` ref 与 `onExport` 函数（按当前时间范围、实例、排序参数调用后端导出接口，Blob 下载）
2. **死锁监控缺少导出按钮**：`Deadlocks.vue` 脚本中已有孤立的 `onExport` 函数但模板无按钮且缺少依赖。本次：
   - 在工具栏"重置"按钮后新增导出按钮（含导出中禁用态）
   - 导入 `exportDeadlocks`、`downloadBlob`、`buildExportFilename`，新增 `exporting` ref
   - `onExport` 改为基于预设时间范围计算 start_time/end_time
3. **死锁监控时间筛选改为预设范围**：移除手动 `datetime-local` 开始/结束时间输入，改为与慢查询分析一致的预设时间范围按钮组：最近6小时（默认）/ 最近1天 / 最近7天。新增 `timeRangeOptions`、`timeRange`、`getTimeRange()`、`onTimeRangeChange()`，`fetchList` 与 `onResetFilters` 相应调整（重置时恢复默认 6 小时）。
4. **i18n 同步**：`deadlocks` 段移除不再使用的 `startTime`/`endTime` 键，新增 `timeRange` 与 `ranges.{6h,24h,7d}` 键（zh-CN / en-US）。

## 变更原因
- 上一合并（分支 trae/agent-5sBCN4）中导出功能实现不完整：SlowQueries.vue 只合入了模板按钮、Deadlocks.vue 只合入了脚本函数，导致功能不可用（用户反馈问题 1、2）。
- 用户要求死锁监控不要手动选择时间范围，改为预设快捷范围以提升易用性（用户反馈问题 3）。
